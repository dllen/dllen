# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This repository is a GitHub profile README (`dllen/dllen`) that is auto-updated by GitHub Actions. `README.md` contains HTML comment markers (`<!--START_SECTION:...-->` / `<!--END_SECTION:...-->`) that workflows replace with generated content.

## Repository structure

- `README.md` — Profile README. Do not manually edit content between `<!--START_SECTION:...-->` and `<!--END_SECTION:...-->` markers; it is overwritten by workflows.
- `src/getTopFollowers.py` — Queries the GitHub GraphQL API and regenerates the top-followers table in `README.md`.
- `src/listPosts.js` — Parses `atom.xml` and regenerates the latest blog posts list in `README.md`.
- `AWESOME-STARS.md` — Generated by the `starred.yml` workflow; do not edit manually.
- `.github/workflows/` — Automation that updates the README and related files on schedule, push, or `workflow_dispatch`.

## Build, test, and lint

There is no build system, package manager configuration, linter, or test suite in this repository.

## Running scripts locally

Most workflows can only run in GitHub Actions, but the two local scripts can be executed manually:

### Update top followers

```bash
pip install requests
python src/getTopFollowers.py <github-handle> <token> README.md
```

The token must have access to the GitHub GraphQL API.

### Update blog posts

```bash
curl -L -o atom.xml https://scp.net.cn/blog/atom.xml
node src/listPosts.js
rm atom.xml
```

## Required secrets

Workflows need these repository secrets (Settings → Secrets and variables → Actions):

- `STAR_FORK_TOKEN` — Classic GitHub personal access token with the `public_repo` scope. Required by `star-fork.yml` because `GITHUB_TOKEN` cannot update repository descriptions.
- `WAKAPI_BASE_URL` and `WAKAPI_API_KEY` — Used by `wakatime.yml` to fetch coding stats.
- `GITHUB_TOKEN` — Provided automatically by GitHub Actions; used by `blog-posts.yml`, `starred.yml`, and `topFollowers.yml`.

## Local secrets

`.env` is gitignored and stores `GH_TOKEN` for local script runs. Verify it is never committed.

## Testing workflow changes

Validate workflow changes by triggering the workflow manually (`workflow_dispatch`) and inspecting the generated markers in `README.md` or the workflow logs.
